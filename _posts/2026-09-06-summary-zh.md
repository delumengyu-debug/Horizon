## [图解 Rust 的虚表：trait 对象在内存中的工作原理](https://sofiabelen.github.io/projects/visualizing-rusts-vtables-how-dyn-trait-works-in-memory/) ⭐️ 8.0/10

索菲·贝伦发布了一篇图解指南，解释 Rust 如何通过虚表（vtable）为`dyn Trait`实现动态分发，并详细说明 trait 对象的内存布局及约束其使用的对象安全规则。文章写于本周，使用了 Rust 当前术语——现在将对象安全称为“dyn 兼容性”。 理解虚表布局对在性能敏感或嵌入式代码中使用 trait 对象的 Rust 开发者至关重要，这部分开发者需要知道间接开销与内存负担。文章还阐明了 Rust 动态分发与 C++将静态、动态多态分离的方案之间的设计张力，因此对跨语言对比很有价值。 Rust 的 trait 对象是“胖指针”——将数据指针与虚表指针配对，这与 C++把虚表指针直接嵌入每个对象内部不同。文章涵盖零大小类型（ZSTs）这类边界情况：它们没有内存地址，因为其同一性靠编译期的所有权机制跟踪；文章还指出“对象安全”在 Rust 官方文档中已正式改称“dyn 兼容性”。

hackernews · torutofu · 9月5日 13:31 · [社区讨论](https://news.ycombinator.com/item?id=49576343)

**背景**: 在 Rust 中，`dyn Trait`是 trait 对象，它允许在运行时进行动态分发，与泛型所用的静态分发相对。当值被存为 trait 对象时，编译器会生成一个虚表，内含指向具体实现方法的函数指针；胖指针则同时保存数据指针和虚表指针。“dyn 兼容性”规则（即原先的“对象安全”）会排除按值接收`Self`、需要`Sized`等方法，因为具体类型被隐藏在 trait 对象背后，所以这些规则确保 trait 能被这样使用。

谷歌发布了一篇研究论文，介绍了 Beyond Zero 安全模型，它针对 AI 时代将零信任（Zero Trust）扩展到了自主 AI 智能体。访问决策从应用级别下放到具体资源和操作层面，结合静态授权控制与 AI 驱动的动态决策，实现机器级速度的强制访问控制。 此事意义重大，因为它将影响深远的 BeyondCorp 模型扩展到了保护企业中自主 AI 智能体这一新兴挑战上。鉴于 BeyondCorp 曾塑造了现代零信任实践，Beyond Zero 有望为组织在智能体以机器速度运作时如何管理安全树立新的范式。 Beyond Zero 模型在具体资源上的单个操作层面评估授权，而非授予对整个应用的广泛访问权限。该模型基于五个核心原则构建，其中“基于资源和操作的安全”是关键基础，以满足对人和智能体进行细粒度、实时决策的需求。

## [Harrison Chase 详解 Deep Agents 上下文压缩：卸载而非清除](https://x.com/hwchase17/status/2096285996304433248) ⭐️ 8.0/10

Harrison Chase 在推文中概述了 Deep Agents 的上下文管理设计，指出压缩应减少发送给模型的内容，而不应删除底层工作历史。他描述了一种基于文件系统的流程：将较大的工具结果和较早的消息卸载到文件系统目录，并在从可见上下文中移除前生成摘要。 这一设计之所以重要，是因为长时间运行的 LLM agent 会面临上下文无限增长的问题，导致成本与延迟上升，并因早期细节丢失而出现“上下文腐坏”(context rot)。通过将持久化内容与模型可见内容明确分开，Deep Agents 提供了一种可供 agent 开发者采用的实际模式，使 agent 在长任务中保持准确与经济。 每个 agent 都会获得一个真实或虚拟的文件系统；过大的工具输出会被写入 `/large_tool_results`，并用预览代替；较早的消息会先移至 `/conversation_history`，再生成摘要。agent 还可以主动调用 `compact_conversation` 工具，以执行相同的卸载并总结逻辑，该逻辑已在 Deep Agents 的 summarization middleware 中实现。
